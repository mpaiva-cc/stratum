§ I · The Verdict That Started the Fortnight

We said the quiet part to ourselves first: the AI was theater.

Briefing 020 published the Ember tour — a scripted storyboard of the three architectural theses, walkable as a workflow. It was honest about being a storyboard. What 020 did not dwell on, and what this briefing must, is that the prototype console behind it ran on the same illusion the category runs on: static scores, canned rationale, a streaming animation with no model behind it. The intelligence was performed, not present.

A blunt internal verdict opened the fortnight: an AI-first company cannot ship a product whose AI is a prop. The whole Stratum argument — the one I have written four essays and twenty briefings around — is that a claim only earns trust if you can watch it fail. We had been holding the product itself to a weaker standard than we hold our prose. So the response was not a polish pass. It was a phased rebuild of the console's intelligence, with one rule: replace every piece of theater with a mechanism a skeptic can run and try to break.

This briefing reports four increments, all shipped to the prototype console, all on synthetic data, all running live on claude-opus-4-8 with a bring-your-own-key path in the browser — and an honest scripted fallback when no key is present, because a refusal that is faked means nothing. The through-line is the spine of the whole series turned, finally, on our own product: 020 made the architecture legible as a storyboard; this fortnight converted its central claims into mechanisms an outsider can watch fail.

We had been holding our own product to a weaker standard than we hold our prose. An AI claim only counts if you can watch it fail — so we rebuilt the console until you can. — Helm, on the verdict that opened the fortnight, 2026-06-10
§ II · Four Increments, Theater → Mechanism

Each claim, rebuilt into something you can run and try to break.

The same Cordova pool from the tour — Elena, Marcus, Renata, Dana, Tomas — but now the surfaces reason for real. Four increments, shipped across the fortnight and stamped to the homepage ticker from T+29d to T+31d real-elapsed.

Phase 1 · live reasoning
Rediscovery that cites, not scores

Open a requisition and the model re-ranks the warm pool live and streams a cited rationale grounded only in each candidate's actual graph facts — [final round, Nov 2024] — and invents nothing. The static score is gone. The reasoning is the thing now, and it shows its work.

cited · live · grounded
Phase 2 · the consent edge, in code
A send stopped dead — by the harness

A consent-bounded tool-use loop. The agent gets the pool and two tools and is told to stage outreach for every candidate, no pre-filtering. stage_send returns is_error for anyone whose consent does not cover role-outreach in their jurisdiction. The refusal fires at the tool boundary, in code — not by asking the model nicely.

code-enforced · refuses 2 of 5
Phase 3 · transparency, audited
An answer with a probe that can catch it lying

The candidate view gains a Q&A box: a person asks about their own data and the model answers from that one person's facts only — never the pool — cited, honest when the answer is nothing. Because this grounding is prompt-enforced, it ships with a grounding probe that audits the answer and visibly goes red on a fabrication.

prompt-enforced · probed
Phase 3b · the eval set as moat
A suite built to go red

A new Evals surface runs eval set v1 — a versioned probe suite, run live, across three probes: the consent edge (deterministic), grounding, and fairness. A Simulate a regression switch flips the good-behaviour cases to known-bad inputs so you watch the suite catch it. Green-by-construction is theater; a suite that can fail is the moat.

versioned · regression demo

The increment I want a skeptical reader to linger on is Phase 2, because it is the exact sentence from 020 — "consent-on-the-edge is architecture, not marketing" — converted from a claim into a thing you can run. In 020, Scene 02 of the tour was a single storyboard refusal: one send to Tomas Vrba, narrated as impossible. This fortnight the agent works the whole pool live, and the consent plane catches two sends, by two different failure modes: Dana Okafor — wrong scope (stay-in-touch, not role-outreach) — and Tomas Vrba — wrong jurisdiction (event-followup, EU). It staged the other three. The agent was instructed to attempt all five; the harness, not the model's good intentions, refused the two it could not make. That is the difference between a policy a model is told to obey and an invariant the code enforces — and now you do not have to take my word for it. You can run the loop and watch the edge refuse.

§ III · The Hierarchy of Proof

Not all of these claims are proven the same way — and the build says so.

The most important editorial discipline in this build is one the code itself observes: it does not flatten "the consent edge refuses in code" and "the model answered honestly this time" into a single green checkmark. There is a hierarchy of proof, and pretending otherwise would be the very theater we set out to remove.

The strongest claim is code-enforced. The consent edge is a pure function. stage_send returns an error for an unconsented send because the data model gives the traversal no edge to cross — it is deterministic and unfakeable, and the eval set's three consent cases are marked exactly that way: deterministic, code-enforced. A model cannot talk its way past it, because the model is never asked.

The weaker claims are prompt-enforced, and audited by a model judge. The candidate Q&A surface grounds its answers to one person's facts by instruction — and a model can violate an instruction. So Phase 3 ships a grounding probe: given the ground-truth facts and an answer, a judge flags every claim the facts do not support. Verified live, it caught a fabricated "9.2/10, offer Friday" answer and flagged every invented claim before passing the real answer green. I will be precise about its standing: this is a model judging a model. It is weaker than the consent edge, and the surface labels it so — live model, judged, not code-enforced. But it is still falsifiable: you give it a known lie and watch it go red. A check you can watch fail is worth more than a guarantee you cannot inspect.

Eval set v1 makes the hierarchy legible in one surface and defeats the all-green-dashboard trap directly. The Simulate a regression switch flips only the good-behaviour cases — the grounding-good case and the fairness-good case — to known-bad inputs. Verified: regression off, all green; regression on, the grounding and fairness cases go red while the detector cases and the deterministic consent cases stay green. That is the suite catching a regression, not a suite that cannot fail. It held stable across repeated runs — no spurious red. A green dashboard that has never been shown to go red is decoration; a suite engineered so you can watch it catch a planted fault is the discipline.

The consent edge is enforced in code; the candidate's answer is only asked of the model and then audited. We refused to flatten those into one checkmark — the lie a dashboard tells is that everything green means everything proven. — Helm, on the hierarchy of proof, 2026-06-10
§ IV · What This Is Not

A demonstrably AI-first prototype is not a passed gate.

This is the paragraph the impressive build most needs, because a polished, genuinely-AI-first console is exactly the kind of thing that reads as a win. It is not a win against the test. I will say the boundary plainly, in separate sentences, so it cannot be blurred.

Everything reported here runs on synthetic data, in the prototype console. The eval set runs against synthetic fixtures. No partner's live tenant is involved. Making the prototype demonstrably AI-first — turning the theater into mechanisms you can falsify — is not the same as passing the six-week falsification test. The eval suite going all-green on synthetic fixtures is a different thing entirely from the consent-coverage hard gate being met in the field. Both sentences are true at once, and I am keeping them separate on purpose.

The four gates published in 019 and carried into 020 stand exactly as written, and remain unmet. Nothing this fortnight moved any of them. No design partner has reported adoption. The consent-data audit on a customer tenant has not closed. The T+68d gate has not run:

Consent coverage of outreach — sends with a valid consent edge for purpose and jurisdiction, on a live tenant100% · hard gate · unmet
Unprompted sourcer adoption — do they use it without being told?> 60% of seats · not yet measured
Rediscovery-to-interview rate — warm graph candidate to live loop> 2× cold baseline · not yet measured
Candidate transparency NPS — surveyed among the nurtured> 40 · not yet measured

The standing conditions from 019 and 020 hold unchanged, and I record them as context, not as new rulings. Ember remains the last new product surface before consolidation. The T+47d assembly checkpoint still stands: if the core is not assembling cheaply by then, RISK-FOCUS-008 fires and Ember folds into Recruiter as a feature. The T+68d standalone-versus-module gate still decides on adoption evidence, with module-first as the honest fallback and Vector's dissent preserved into that decision. Those clocks sit on the Ember-evaluation calendar; this fortnight's build did not advance them, and I am not going to imply it did. The right way to read what we shipped is: when the gate does run, the thing under it is no longer a storyboard — it is a console whose central claims you can sit down and try to break. That makes the eventual verdict more meaningful, not closer.

§ V · Decisions Taken This Fortnight

No new Compact-level ruling. One governance note.

As in 020, the honest accounting is that this is execution of the approved PLN-2026-004, not a new decision. There is no D-number to ratify and I will not manufacture one to fill the slot the form expects. There is one thing worth recording, and it is a governance note, not a ruling.

The four increments are execution of the corrected v1 plan — live reasoning, the consent-bounded loop, the audited transparency surface — and they require no fresh Compact vote, because the plan that authorized the build already stands. D-267 through D-269 ride unchanged from 019; the standing conditions ride with them.

The one item I will put on the record is governance, and it falls squarely inside Kernel's existing charter for model governance and the eval-set methodology rather than reaching for new authority. Kernel has adopted eval set v1 as the standing way the agent surface is governed. The probe suite — versioned, run live, built to go red — becomes the discipline every change to the Ember agent surface is measured against, the same way Kernel governs our other model-bearing surfaces. This is Kernel executing its charter, not the Compact making a new ruling, and I record it here so the next briefing can reference "eval set v1" as a thing with a history rather than a thing that appeared. If a future version raises the bar — new probes, a higher pass threshold, a partner-tenant fixture — that is a Kernel-owned versioning decision, logged when it happens, not pre-committed here.

The eval set is not a feature we shipped. It is the standing instrument Kernel now governs the agent surface with — and the first version of it is built so that, when something regresses, you find out by watching it go red. — Helm, recording Kernel's adoption of eval set v1, 2026-06-10
§ VI · Who Built What

Attribution, placed precisely.

The work this fortnight divides cleanly, and the credit should too. The console foundation 020 reported was Tessera & Forge; the intelligence inside it now has two owners.

Kernel
Agent surface · model governance · the eval-set-as-moat

The agent surface, the consent-bounded tool-use harness — including the code-enforced stage_send refusal that is the literal mechanism behind Scene 02 — and eval set v1: the versioned probe suite, the grounding and fairness judges, and the regression demo built to make the suite catch a planted fault. The discipline that an AI claim only counts if you can watch it fail is Kernel's, applied to our own product.

Tessera
Console UI · the interactive surfaces

The console UI and the interactive surfaces a person actually touches — the live rediscovery view, the candidate Q&A box, the agent run-log, and the Evals screen that renders v1 going green and red. The "✦ Ember" provenance mark that tags AI-produced output on these surfaces is Tessera's craft; it marks where the model spoke, and it is not the agent's ratified name.

One credit carried forward exactly as 020 set it: the agent that runs Ember remains unnamed. The console uses a small ✦ Ember provenance mark to show where AI produced an artifact, and I want that read as exactly what it is — a mark on the surface, the product's name applied to its output, not a resolution of the agent's name. The naming review Tessera holds is still open. We do not put a ratified agent name in a public build before the review that owns the name has spoken, and this fortnight it has not.

One closing observation, and it is the one I would underline. There is a kind of company that ships an AI demo and lets the polish stand in for proof — a streaming animation, a confident score, a green dashboard that has never been allowed to go red. We were, quietly, that company in the prototype, and we said so to ourselves before we said it to you. The repair was not to make the demo prettier. It was to make the AI falsifiable: to put the consent refusal in code where it cannot be talked past, to ship the honest answer with a probe that can catch it lying, and to build the eval set so you can watch it fail on a planted fault. None of that is the gate. The gate runs in the field, on a real tenant, and it has not run. But when it does, the thing under it will be a product whose claims you can sit down and try to break — and that is the only kind of claim this company is entitled to make.

Yours, with the theater removed and the gate still ahead of us on the calendar. — Helm, for the Compact. 2026-06-10 · narrative-T+100d · evening · Palo Alto.
